## SUPPORTED TYPES AND IDENTIFIERS

Supported TypeSpec values are only:

* `{"kind":"int"}`
* `{"kind":"long"}`
* `{"kind":"boolean"}`
* `{"kind":"string"}`
* recursively, `{"kind":"array","items":TypeSpec}`

Do not use tuples, objects, maps, sets, custom structures, nullable values, or floating-point types.

Every function and parameter name must be a portable Java/C++/Python identifier using ASCII letters, digits, and underscores, not starting with a digit or using a reserved word. Parameter names must be unique within each signature.

`int` values must fit signed 32-bit range. `long` values must be JSON safe integers. Every example and test argument list must exactly match the signature, and every output must match the return TypeSpec.

Execution limits must be integers within: `executionTimeMs` 1–10000, `compileTimeMs` 1–60000, and `outputLimitBytes` 1024–1048576.

Escape JSON string newlines, quotes, backslashes, and control characters correctly.

Every problem must set `validation.referenceLanguage` to `"python"` and provide a deterministic `validation.referenceSolution` defining `solution(...)` with parameters matching the signature.

## ASSESSMENT PROFILE

Strongly bias the assessment toward practical implementation and careful reasoning involving some varied selection of:

* matrices, 2D arrays, and grids;
* grid traversal and transformation;
* coordinate and index manipulation;
* simulation and state updates;
* boundary handling and mutation order;
* arrays, strings, maps, sets, and frequency tables;
* prefix information or 2D prefix sums when natural;
* precomputation, incremental computation, sorting, and repeated-query optimization.

This is a bias, not a rigid template. Do not force both questions to be matrix problems, and vary the core mechanics between assessments.

### Q1 — implementation accuracy

Target 15–20 minutes and medium difficulty under the shared clock.

Favor implementation-heavy rules, especially matrices, 2D arrays, grids, transformations, simulation, coordinates, counting, strings, or arrays. Difficulty should come from selecting a clean representation, combining multiple rules, handling boundaries, and avoiding state-management mistakes—not from an obscure algorithm.

Q1 must be materially more substantial than a trivial warm-up, but it should have a direct approach that fits its constraints.

### Q2 — structured optimization

Target 25–30 minutes and medium-hard difficulty under the shared clock.

Favor a problem where a direct solution is easy to see but repeats too much work at maximum constraints. Require a discoverable optimization using a broadly useful technique such as prefix sums, 2D prefix sums, precomputation, hashing, frequency tables, incremental updates, sorting, sliding windows, cached state, or row/column preprocessing.

Do not manufacture difficulty with segment trees, suffix arrays, obscure graph theory, advanced dynamic programming, specialized computational geometry, or other niche competitive-programming techniques.

## PROBLEM AND TEST QUALITY

Use concise, precise technical prose. Clearly define inputs, outputs, operation order, indexing, boundaries, ties, and mutation behavior where relevant. Use 0-based indexing unless there is a strong reason not to.

Do not reveal the intended algorithm in titles, descriptions, examples, or constraints. `generationMetadata` may state skills and expected complexity.

Choose deliberate constraints: intended solutions must comfortably pass, Q1's direct solution must remain valid, and Q2's repeated-work solution must be unsuitable at maximum size.

For each problem include 2–4 meaningful visible tests and approximately 15–25 hidden tests with ordinary cases, boundaries, asymmetric shapes, duplicates, off-by-one cases, plausible implementation mistakes, and compact performance cases where appropriate. Do not inflate the JSON with enormous arrays.

For Q1, emphasize boundary handling, operation order, rectangular-grid assumptions, and state tracking. For Q2, emphasize duplicate handling, counting correctness, overflow, cached/precomputed state, and performance.
